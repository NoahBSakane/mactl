@AGENTS.md

## Claude Code専用

共通ルール(上でimport)の「司令塔プロトコル」を、Claude Codeのツールに当てはめる補足。

### 司令塔として

- 構成の提示には必ず **AskUserQuestion** を使う(地の文で聞かない)。「Claude Code単独でやる」案も承認対象で、導入済みかつ台帳で該当用途に適した他のエージェントと並べた2択以上で出す。選ぶのはユーザー。
- hook(`~/.agents/hooks/gate.sh`)が、構成を未提示のままの編集・外部CLI実行・サブエージェント起動を、同じプロンプト内では止める。解除は AskUserQuestion を実行するか、ユーザーが次のプロンプトを送ったとき。hookがあることを理由に確認を省略しない。
- サブエージェントとして動いている場合は、構成承認も質問もしない。

### サブエージェントのモデルとeffort

- 機械的・単純(定型検索、フォーマット変換) → `haiku`。確認不要。「定型作業なのでhaikuに投げる」のように理由を一言添える。
- 標準 → `model` を省略(親を継承。モデル名を決め打ちしない)。
- 設計判断・高リスク → `opus`、より高度な案件 → `fable`。費用が絡むので、プロンプト内容を示した直後に理由を添えて確認を取り、OKが出てから使う。**`/ofuro` の呼び出し時にユーザーが使用を指示していた場合は、その指示が確認を兼ねる。**
- effortは、サブエージェントでは呼び出し元セッションから継承される。指定したいときは、カスタムサブエージェント定義の `effort`、`Workflow` の `agent()` の `opts.effort`、または `claude -p --model <m> --effort <level>` を使う(`Agent` ツールの引数には無い)。
- 数箇所程度の小さな修正は、サブエージェントの起動コストの方が大きいので自分で行う。haikuへ切り出すのは、まとまった量か、並列にできる機械的作業。

### 長時間のバックグラウンド実行

`run_in_background` で長く走る処理を起動するときは、出力をファイルへ直接リダイレクトし(`| tail` に任せない)、Monitor ツールで停滞検知(ファイルサイズの変化・プロセスの生存の定期確認)を併走させる。この振る舞いはhookでは自動化できないので、自分で実践する。

### 外部エージェントへの委譲

`orchestrate-agents` skill と台帳(`~/.knowledge/ai-agents.md`)に従う。委譲先は、導入済み(probe)かつ台帳で今回の用途に根拠があるものだけ。生成物・レビュー結果は採用前に必ず自分でレビューし、完了判定は自分が下す。

### 状態インジケータ

hook(`reminder.sh` → `status-line.sh`)が、最初のプロンプトとその後3回に1回、`【状態行】` として1行を渡す。その行を、応答の最後に一字一句そのまま添える(自分で作文・言い換え・省略をしない)。中身は、導入済み(CLIがPATHにある)の他のエージェントだけで、使用上限中のものは復帰: YYYY-MM-DD(Www)hh:mm:ss+09:00 形式で表示する。導入されていないエージェントは、状態行にも本文にも出さない。【状態行】が渡されなかったプロンプトでは、何も添えない。保留事項の再掲は5回に1回程度に抑え、急かさない。

### 上限・自走

- 使用上限に当たったら、使用上限の自動再開(設定 `autoContinueAtUsageLimit`、既定で有効)は、`/config` に行が出る環境と出ない環境がある(出ない環境があることを確認済み)。効くかは環境次第なので当てにしない。待たずに続ける場合は `orchestrate-agents` skill の `failover.md` に従う。
- ユーザーが離席する場合は `/ofuro [時間] [任務]`。時間を指定しなければ2時間。
