# ofuro(お風呂モード)

ユーザーは戻るまで一切応答できない。リスクは本人が織り込み済みなので、**確認せずに進める**。

開始・終了・時間の管理はhookが行う(`/ofuro [時間] [任務]` で開始、`/ofuro off` で終了、時間の指定が無ければ2時間)。hookが始めの文脈に出す「お風呂モード開始」の行に、期限・許可モデル・完了マーカーのパスが入っている。hookが無い環境では、ユーザーが示した時間を目安に、同じ振る舞いで進める。

## 振る舞い

1. **質問しない。** 質問UI(AskUserQuestion等)は使わない(hookが拒否する)。迷ったら、推奨案を選んで進める。エージェント構成も、台帳の適切用途に従って自分で決める(承認は不要)。
2. **判断を残す。** 質問になるはずだった判断を、`~/.agent-state/ofuro-journal.md` に追記する:

   ```markdown
   ## 2026-10-06 19:42 — 問い: (何を決める必要があったか)
   - 選択肢: A / B
   - 採用: A — 理由(可逆性も一言)
   ```

3. **外部に出る・壊す操作は、止めずに実行内容を記録する。** push・公開・メッセージ送信・削除などは、ジャーナルに「何を・どこへ」を1行残して実行する。
4. **権限プロンプトや分類器に拒否された操作は、止まらない。** 「保留」としてジャーナルに残し、他の作業を続ける。
5. **Opus/Fableは、許可されている場合だけ。** 起動時の行の「許可」に含まれるモデルだけを使う(含まれなければ標準モデルで進める)。
6. **節目で `.agent-handoff/STATE.md` を更新する。** 途中で使用上限などに当たっても、別のエージェントが引き継げるようにする。

## 止まってよい場合(これ以外では止まらない)

- 認証情報の漏洩を確認した、または漏洩する直前の操作に気づいた
- 侵害の兆候(身に覚えのないプロセス・外部通信・変更)を検知した
- 第三者のデータや環境に、即時の被害が出る操作に気づいた

止まる場合は、状況をジャーナルとレポートに書き、PushNotificationが使えれば通知する。

## 終了

全て完了した、または時間が来たら:

1. `STATE.md` を最新にする。
2. `~/.agent-state/ofuro-report-<日時>.md` を書く: **完了したこと / 未完 / 保留(拒否・見送った操作) / 判断ログの要点**。
3. 完了の場合は、起動時の行にある `.done` マーカーのパスを作成する(`touch`)。時間切れの場合はhookが最後の1ターンを使わせるので、その中で書く。
4. PushNotificationが使えれば、レポートの要点を通知する。ユーザーが戻ったら、レポートを要約して報告する。

## 手元を離れる前の準備(ユーザー向け)

無人で進めるには、権限モードを auto にしておく(Claude Codeは Shift+Tab)。manualのままだと、権限プロンプトで止まる。事前に `fewer-permission-prompts` skill で許可リストを整えておくと安定する。
