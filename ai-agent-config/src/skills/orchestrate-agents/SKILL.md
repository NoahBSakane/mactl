# orchestrate-agents

あなたが最上位のセッションとして、タスクを他のエージェントへ振る/構成を提示するときの手順。サブエージェントや委譲先として動いている(`AGENT_DELEGATED_BY` がある、または委譲元が明記されている)なら、この skill は使わず、依頼されたタスクだけを実行して「変更点 / 残課題 / 影響範囲」を報告する。

## 手順

1. **現状把握。** `~/.knowledge/bin/agents-probe.sh` を実行する(`--check` を付けると、台帳が記載するフラグが各CLIに残っているかも検査する)。`ready` のものだけが委譲候補。`no-auth`(未認証)は候補にしない。出力末尾に「台帳の確認が14日を超えた」とあれば、作業を止めずに、区切りの良いところで `refresh-registry` skill を実行する。
2. **候補の選別。** `~/.knowledge/ai-agents.md`(台帳)の各エージェントの「適切用途」を読み、今回のタスク種別に根拠(格付けA〜C。Aは独立したベンチマーク、B〜Cは公式・ベンダーの情報)があるものだけを残す。根拠が無いもの(D)は並べない。ユーザーが指名したエージェントがあればそれに従う。
3. **構成の提示と承認。** 質問UI(Claude Codeなら AskUserQuestion、無ければ番号付き選択肢)で、**自分で抱え込む案を含む2案以上**を出す。各案は「担当・理由」を1行ずつ。サブエージェントでOpus/Fableを使う案は、費用が絡むので、プロンプト内容を示してから確認する。ユーザーが修正意見を出したら、納得が得られるまで実行しない。
4. **指示の作成。** `references/protocol.md` のフォーマット(指示5項目)で書く。指示の冒頭に「あなたは委譲先です。構成承認と質問は不要です」と1行入れる(環境変数がhookやプロンプトに届かないエージェントがあるため)。渡すのはスコープ・関連パス・成功基準・関係する指示ファイルの制約だけ。会話が長いときは生ログではなくタスク単位に要約する。
5. **実行。** 台帳の「非対話」「承認」「モデル/思考」の記述どおりに起動する。毎回守ること:
   - 環境変数 `AGENT_DELEGATED_BY=<自分のセッション/エージェント名>` を付ける(委譲先のhookが承認を求め直さないため)。Museはhookへ環境変数を渡さないので、無人実行のフラグ(`--disable-approval`)で代える。
   - 非対話実行は確認プロンプトを出せないので、台帳の自動承認フラグを付ける。委譲先が確認なしに操作できる分、手順6のレビューが唯一の歯止めになる。
   - モデルとeffortは毎回明示する。モデル名は probe の出力から選び、決め打ちしない(世代交代で変わる)。軽量・機械的 → 最小階級・low、標準 → 主力(workhorse)・medium、難度が高い → 最上位(frontier)・high以上(階級は `probe` が出すモデルの説明で分かる。effort は思考の深さ)。
   - 大きな生成や、既存コードへ影響させたくない作業は worktree か別ディレクトリで行う。
   - 外部CLIに渡す文へ秘密情報を入れない(hookも検査する)。
   - Museは、他エージェントの個人rulesの自動取り込みを設定で止め、専用のrules(`~/.config/muse/AGENTS.md`)を持たせてある。未配備の環境では `--no-foreign-personal-context` を付ける。
   - 分割の目安: 大きな案件は、1本に詰めず中〜小の案件に分けて回す方が利用枠と噛み合う(委譲するかどうかは共通ルールの司令塔プロトコルに従う)。富豪的な並列実行はしない。失敗したら粘らず、別の候補か自分で処理する。
   - 実行が**使用上限(usage limit)**で失敗したら、そのエージェントを当面候補から外す。`mkdir -p ~/.agent-state/unavailable && printf '%s\t%s\n' <復帰時刻のepoch> '<メッセージ>' > ~/.agent-state/unavailable/<agent>.txt`(復帰時刻が分からなければ6時間後)と記録すると、probeが `limit` と表示し、期限が来れば自動で戻る。
6. **受領とレビュー。** `references/protocol.md` の受領基準を満たすまで受理しない。生成物・調査結果は採用前に自分でレビューし、完了判定は自分が下す。他者が書いたコードのレビューを外部に任せた場合、委譲するのは指摘の列挙までで、採否の判断は委譲しない。委譲先自身が書いたコードのレビューを、同じ委譲先に任せない。
7. **長時間・引き継ぎ。** 節目で `.agent-handoff/STATE.md` を更新する(`references/handoff.md`)。使用上限に近い、または到達したときは `references/failover.md`。
