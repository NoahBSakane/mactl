# 書き方の好み(Slackの返信案・Notion Ticket)

ユーザー(n_sakane)名義で文章を書くときの、本人の実際の修正から導いた好み。書く前に、本人の過去の文章を読んで確かめる(少数の例で決めない)。

## Slackの返信案

ユーザー名義の返信案は、本人の過去の投稿(`slack_search_public` で `from:<@<自分のSlackユーザーID>>`。公開チャンネルで足りる)を検索して、口調を確認してから書く。

- 書き出しは「お疲れさまです！先日は共有ありがとうございました:ojigi_ehachi2:」の型。結果の強調(「本番に反映しました！」)は避け、「原因を特定し、修正しました」と淡々と書く。
- 原因の説明は1文にまとめる。「〜おりました」と少し丁寧に書き、「チグハグな回答になってしまう原因でした:thinking_face:」のように、評価の言葉で締めてよい。2文に分けて口語で書く(「〜寄ってました…」)のは過剰。
- 見出しは「直したこと:」ではなく「修正点:」。箇条書きは短く、補足の括弧は付けない。
- 絵文字は役割で使い分ける: 不確かさ・原因の説明は `:thinking_face:`、お礼・お願いは `:ojigi_ehachi2:`、良い知らせ・締めは `:smile_cat:`(文中に何度も使わず、最後に1回)。
- 相手の発言は `>` で引用してから答える。メンションは1行目に単独で置く。
- 返信案は最初から短く書き、補足は求められたときだけ足す。Slackへ貼るとメンション記法(`<@U…|名前>`)は文字のままになるので、貼ったあと入力し直すよう一言添える。

## Notion Ticket(部署のTickets)

書く前に、作業者が本人のTicketを10件以上読んで、書き方を導出する。Tickets DB: `collection://<TicketsデータベースのID>`、本人のNotionユーザー: `<NotionのユーザーID>`。根拠にするのは、本人が書いた欄(対象・対処・結果・作業者記入欄)だけ。「依頼」欄など依頼者の文と、AIの要約を貼った部分(「。」や太字が多い)は根拠にしない。反例が少数なら、その反例は無視してルールとして採る。

表記の規則:

- 見出しのない複数の列挙は、必ずトグル(`<details>`)にする。
- `:` は、子が1つだけの行や、埋め込みの直前の行に付ける。トグルの見出しや、トグルを持つ行には付けない。
- 1行の中で「。」を使わない。節をつなぐときは半角「; 」。行末にも「。」を付けない。
- インラインコード・リンク・mentionの両端に半角スペース(「、」の直後や「:」「;」の前も)。
- ラベルは半角の「ラベル: 値」(全角「：」は使わない)。区切りに「 … 」、経路に「 → 」、英語の並びに「 / 」「, 」(全角「／」は使わない)。
- カタカナ語は省略しない。省略するならローマ字の頭文字(RM、PBA、BQ、MC、CC)。「メーリス」「スプシ」は不可。
- 語末の長音は、固有名詞以外はJIS Z 8301に則って省く(長音を除いて3音以上なら省く: ユーザ、トリガ、サーバ、ブラウザ。2音以下は残す: キュー、スター)。
- 英語の技術用語は漢語的な日本語にする(allowlist→許可一覧、dry-run→試行、effort→推論強度)。機能名・製品名・仕組みの用語(`rich_text`、Webhook、Function CallingのTool、ClaudeのSkill等)はそのまま。
- 並列の区切りは、同格の語と語は「・」、どれか1つを選ぶ選択肢は「 / 」。
- 手順の文末は「〜する」。手順の中身のトグルは、手順の行が「実装」を言っていれば見出しを「内容」、そうでなければ「実装内容」。
- コードブロックは、中身がJSONでも言語を `yaml` にする(意図したルール)。
- 助数詞は半角数字に直接付ける(1分、3回)。物理単位だけ `` `1 [MB]` `` の形。
- タイトルにも本文にも太字を付けない。
- 「; 」は1行に1回、前の本体に従属する付け足しにだけ使う。付け足しは、①本体の説明・理由・所感をくだけて書くもの(例: 「一旦立てる; 移行ﾒﾝﾄﾞｸｻ」)か、②本体が当てはまらない場合(例: 「…を対象と; 単純な月初だと漏れが生じる虞有」)。同じ重さの別の事実は「; 」でつながず、別の箇条書きに分ける(分けた結果、見出しのない列挙になればトグルにする)。
- 送り仮名を省いた簡潔形(確認待、対応済、有、無)。ただし連体形は「設定済みの」。
- 理由は「為」。常体・体言止め、または「〜する」。敬語は使わない。「〜の旨」「如何」などの硬い語。
- 他人の名前はローマ字フルネームのインラインコード＋「さん」(例: `` `Taro Yamada` さん ``)。名前は `notion-get-users` の name を使う。苗字の漢字表記は不可。`<mention-user>` は相手に通知が飛ぶので使わない(2026-09-29に誤って通知を飛ばした)。自分自身だけ `<mention-user>` でよい。
- 本文中の過去の日付は `` `2026-09-15(Tue)` `` の形(インラインコード、曜日付き)。「9/15」は不可。
- 識別子・ボタン名・チャンネル名・値はインラインコード。画面の列名・項目名は「」。外部URLはURL文字列そのものをリンク文字にする。
- SlackのリンクはNotionの埋め込みにする。APIからは作れない(`external_object_instance` は読み取り専用)ので、リンクを単独の行に置いてから、変換を本人に頼む。
- 手順は番号付きリストで、動作で書く(「〜を実装」「〜する」)。空の欄は斜体の「*省略*」。
- 本人が同時に編集していることがある。書き込む直前にfetchし直し、差分だけを当てる。
